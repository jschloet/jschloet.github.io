01 · Explore

How does a sorting machine work?

Four numbers travel along four horizontal wires, from left to right. A comparator connects two wires: the smaller value goes to the upper wire, the larger to the lower wire. Some comparators can act simultaneously, but here you can step through them one at a time.

Which number would you expect to reach the bottom wire? Can you predict what happens before clicking Next step?

03 · Verify

Does your network always work?

Sorting one sample is not enough. Click Find a counterexample in the builder. If your network fails, the computer will show a counterexample — one input proving that it does not always work.

Build something first, then run the tests. A failing input will appear here, with its incorrect output.

Many successful runs do not by themselves establish that an algorithm works for all inputs. But one input that fails is enough to disprove such a claim. Finding a counterexample tells you exactly where to start debugging.

04 · Improve

Can you make it faster?

Two independent comparators can run in parallel. A network is judged by its number of comparators (total work) and its depth (number of parallel steps).

Try the four-wire challenge: can you correctly sort every input using only 5 comparators, arranged in 3 steps?

05 · Explain

Why does it always work?

Testing helps find mistakes. But how could we explain why a sorting algorithm works for every input, without trying them all? One answer is to build it in a way that preserves a useful fact, called an invariant.

Here is an insertion sorting network for three wires. First sort the top two values. Next insert the third value into that sorted pair, using comparisons that move it upward as needed. Follow the construction one step at a time.

Step 0 of 3

Start: After comparing the first two wires, the top two values are sorted, no matter what they are.

Insert: Assume the first k wires are sorted. Compare the next value upward, one neighbor at a time, from the bottom of that group toward the top. Each comparison puts the smaller value above the larger. The new value ends in its correct position, and the other values stay in order. Thus the first k + 1 wires are sorted.

Repeat: Start with one trivially sorted wire, and insert each new wire in turn. This reasoning works for any number of wires and for any numerical values. We have explained correctness using structure, rather than relying on successful test runs.

Key distinction: A failed test disproves correctness. Successful tests build confidence and help debug; a general argument explains why the algorithm must work.

Takeaway

From examples to guarantees

You've moved from trying a few cases to designing reusable instructions, finding counterexamples, and reasoning about why a construction always works. That's a big part of how mathematicians and computer scientists design and analyze algorithms.

The key question: How can we know that an algorithm will work on inputs we've never seen?
